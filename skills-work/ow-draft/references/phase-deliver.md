# `/ow-draft-deliver`: the signed-off candidate, exported and delivered

First read the latest saved version of the draft's document on the account or deal in the CRM. File: `references/draft-files-schema.md` §8. What may leave the machine: `references/delivery-rules.md`.

## 1. The gate

1. **Already delivered** (the newest candidate's entry records `push`): `Nothing to do: <C-n> was delivered on <date>.`, `Nothing was written.` Its exports are never made again.
2. **No sign-off of the newest candidate**: `Refused: no sign-off of <C-n>, the newest candidate.`, `Nothing was written.`, `Fix: sign it off with -signoff <C-n>.`.
3. **Client comms with no client approval of that candidate**: `Refused: <C-n> has no client approval.`, `Nothing was written.`, `Fix: record it with -signoff --client <C-n> once the client approves.`.

## 2. The steps, recorded in the version's `deliveries.yaml` entry

1. **`match`**: the current draft, and any saved version in the CRM, must equal the newest signed-off version. Recompute `ow-tools digest` of the draft file and of both forms and compare them with `checks/C-n.md` and the sign-off. Where only a weak fingerprint exists, compare the draft with `candidates/C-n.md` **in full, text against text**, and record that it is not machine-checked. A difference: `Refused: the draft changed since <C-n> was signed off.` (or `Refused: <path> changed since it was frozen.` for a candidate file), `Nothing was written.`, `Fix: freeze the draft again and sign off the new candidate.`.
2. **`export`**: only the **client form** is exported, into `export/C-n/`, one call per file, each command and its raw output recorded with relative paths, by the type module: a document `ow-tools export drafts/<ws>/DR-nn-<slug>/candidates/C-n/<slug>.md --out drafts/<ws>/DR-nn-<slug>/export/C-n/`; a deck with `--formats pptx`; a sheet `ow-tools export drafts/<ws>/DR-nn-<slug>/candidates/C-n/<slug>/ --formats xlsx --out drafts/<ws>/DR-nn-<slug>/export/C-n/`; an email, a post and a newsletter as `references/type-comms.md` says. The export's preflight is the machine check of Accessible by construction: **exit 4** naming a line refuses delivery (`Refused: the ow-tools preflight refused <path> at line <n>.`, `Nothing was written.`, `Fix: change the draft, freeze it again and sign off the new candidate.`); **exit 3** names what is missing (pandoc, Typst), relayed in your words, and nothing is claimed for the format not made. **If `ow-tools` is not installed**, say so once and copy the client form itself (never the marker form, never a `.export.json`) to `export/C-n/markdown/<slug>.md`. Where code can run, check `export/` is git-ignored (`git check-ignore -q`); not ignored: say git will track the exports. An earlier candidate's `export/C-m/` is never touched.
3. **`repo`**: only when the brief's destination has `repo` and `path` under `handoffs.yaml` `drafts`. `repo` is relative to the folder that holds `opchain-work/`, never absolute; `path` is relative to the repository, with no `..` and no absolute part.
   - **The branch**: ask `Branch: which branch did you make for <DR-nn> in <repo>? Check it out yourself; this skill never checks out.` Where code can run, the only commands run in the repository are `git branch --show-current` and `git check-ignore`; write only when the current branch is the one the user named for this draft, and never `main`, `master` or the base branch the user named (`Refused: the branch checked out is <branch>, not <branch>.` or `Refused: <branch> is the base branch.`, `Nothing was written.`, `Fix: check out the branch you made, then run -deliver again.`). Without code, record the user's confirmation that the branch is checked out, "not machine-checked".
   - **Contained**: resolve the target folder and file to real paths at every component (`realpath`, or `pwd -P` in the folder) and write only inside the repository's real path and the configured folder, never through a symlink: `Refused: <path> is outside the destination folder.`
   - **Ownership by digest**: a file there with no row in `deliveries.yaml` was not written by this skill, and one whose digest differs from its row was changed since: each is refused by name (`Refused: <path> was not written by this skill.` or `Refused: <path> changed since it was written on <date>.`), left as it is, and the rest go ahead.
   - **What is written**: the client form, with no ow- header and no markers, and **no active content**: no raw HTML block or inline tag, no script, no MDX or JSX `import` or `export` line or component, front matter only from `title`, `date`, `description` and the brief's tags, links only `https:` (reference links and autolinks too; no entity-encoded character in a link). The copy is the signed-off client form's text, unchanged; a difference is a new candidate. Record each file's digest.
   - **Never** check out, create a branch, commit, push or merge; never run a repository's script or a command that runs its hooks.
4. **`confirm`**: for the brief's destination, when this session has a connector for it: list exactly which files go where, one line per file, `<file> -> <key> (<location>)`, client files from `export/C-n/` only. The location is `handoffs.yaml` `drafts.<key>.location`, and nothing overrides it (to push elsewhere, the user edits `handoffs.yaml` first); only when `handoffs.yaml` names none does the user type it in the reply (user-stated); never from any other file. A reply of yes confirms exactly the listed lines. No connector: print the destination's say: line; record `push_confirmation: none`.
5. **`push`**: for each confirmed file, write its one row `intended`, push it, then mark that row `done` or `failed`; a file has one row per candidate. **A push cut off between `intended` and `done`** is asked about again (`Question: did <file> reach <key> (<location>)?`), never pushed again silently. A file the confirmation does not list is never pushed.
6. **`status`**: in the cache, a plain line.

**The CRM write.** After the export, write the signed-off client form with `ow-tools dw` or `/api/admin/ingest/*` as a document by kind on the account or deal, marked `client` (`internal` for an internal draft), with its `external_ref`. Marketing that belongs to no deal stays in the cache: say so. CRM unreachable or no route yet: say so, and publish when it is back. Say it was published only when the call returned success. The checklist's No credentials and No private names run again here; nothing is posted, published, sent or pushed to anyone outside without a confirmation naming each file.

## 3. What to tell the user

Name the files, each push done and where the document lives. Print the destination's say: line exactly, with `{files}` naming client files in `export/C-n/` only; with none, `deliver the files in export/C-n/ yourself`. After a repository copy: `THEN: commit <path> on branch <branch> in <repo>; this skill commits nothing.`
