### [F-001] Internal-section stripper misses case/space variants of the marker, so internal content exports silently

**Severity:** HIGH
**Category:** security (confidentiality)
**Location:** `plugins/ow-tools/lib/preflight.mjs:8-9`, `:89`, `:98`
**Fix effort:** S (< 30 min)

**Problem:**
The only control that keeps `<!-- ow:internal -->` … `<!-- ow:end-internal -->` blocks (design §5.2: "such as a quote's internal pricing appendix") out of a client PDF/Word file is three regexes, all case-sensitive and all requiring `ow:internal` with no space after the colon. A marker written as `<!-- OW:INTERNAL -->`, `<!-- Ow:Internal -->` or `<!-- ow: internal -->` matches neither the open/close pattern nor the "stray marker" refusal, and the raw-HTML refusal exempts any full-line HTML comment. Result: preflight returns `ok: true`, `removed_internal_sections: 0`, the export proceeds, and every line of the "internal" section (prices, margins, unit costs) is in the client document. The report even says `"internal sections removed"` in `checked`. The design promises the opposite behaviour for malformed markers ("unbalanced markers refuse"); a variant marker should refuse the same way.

**Evidence:**
```js
// preflight.mjs:8-9
const INTERNAL_START = /^\s*<!--\s*ow:internal\s*-->\s*$/;
const INTERNAL_END = /^\s*<!--\s*ow:end-internal\s*-->\s*$/;
// preflight.mjs:89 — stray-marker refusal, also case-sensitive, no space tolerated
if (/ow:(end-)?internal/.test(l)) bad(i, "stray ow:internal marker");
// preflight.mjs:98 — any full-line HTML comment is exempt from the raw-HTML refusal
if (/<[A-Za-z!/]/.test(l.replace(/`[^`]*`/g, "")) && !/^\s*<!--.*-->\s*$/.test(l)) {
```
Trace for `<!-- OW:INTERNAL -->`: line 58 no match → line 62 no match → line 89 no match (uppercase) → line 98 `!/^\s*<!--.*-->\s*$/` is false → no problem recorded → body keeps the line and everything after it. Nothing in `tests/ow-tools/brand-preflight.test.js` covers a case or spacing variant.

**Why it matters:**
This plugin exists to produce documents a consultant hands to a client. The failure is silent (exit 0, "done", a hash printed as evidence) and the leaked content is exactly the category the design singles out as never leaving the house. Both LLM-authored skills and humans editing the Markdown by hand produce case/spacing variants of literal markers.

**Fix:**
1. Make the three regexes case-insensitive and tolerate whitespace around the colon: `/^\s*<!--\s*ow\s*:\s*internal\s*-->\s*$/i`, `/^\s*<!--\s*ow\s*:\s*end-internal\s*-->\s*$/i`, and widen the stray check to `/ow\s*:\s*(end-)?internal/i`.
2. Belt-and-braces: refuse any HTML comment whose text contains `internal` case-insensitively (`/<!--[^>]*internal/i`) with "an internal marker is misspelt or malformed; write exactly `<!-- ow:internal -->`".
3. Add preflight tests for `<!-- OW:INTERNAL -->`, `<!-- ow: internal -->` and `<!--ow:Internal-->` asserting `ok: false`.

### [F-002] SessionStart hook is not silent on Node < 20: the version guard sits after module linking and after the `hook` short-circuit

**Severity:** MEDIUM
**Category:** quality (hook contract: "never fails the session; silent elsewhere")
**Location:** `plugins/ow-tools/lib/cli.mjs:187-194`, `plugins/ow-tools/bin/ow-tools:8-12`, `plugins/ow-tools/lib/transcribe.mjs:2`
**Fix effort:** S (< 30 min)

**Problem:**
`bin/ow-tools` exits 0 for `hook` only when `node` is absent. When `node` is present but older than 20, control reaches `cli.mjs`, whose Node check runs *after* all static imports are linked and does not special-case the hook verb. Two outcomes, both on every session start in every project: on Node 18.0–18.13 the `availableParallelism` named import from `node:os` fails at link time (SyntaxError, stack trace on stderr, exit 1) before any ow-tools code runs; on Node 18.14–19.x the guard prints "Node.js 20 or newer is required" and exits 3. Claude Code surfaces non-zero hook exits to the user as hook errors. Design §6 assigns the Node ≥ 20 check to "`bin/ow-tools` itself"; the implementation put it one layer too deep. (The `node` found on PATH under the hook is whatever the user's shell default is, e.g. an nvm default, not the runtime Claude Code itself uses.)

**Evidence:**
```sh
# bin/ow-tools:8-12 — only the "no node at all" case is silenced for the hook
if ! command -v node >/dev/null 2>&1; then
  if [ "$1" = "hook" ]; then exit 0; fi
  echo "ow-tools: Node.js 20 or newer is required (macOS: brew install node)" >&2
  exit 3
fi
exec node "$here/../lib/cli.mjs" "$@"
```
```js
// cli.mjs:187-194 — runs after `import … from "./transcribe.mjs"` (which imports availableParallelism) has linked
if (invokedDirectly) {
  if (Number(process.versions.node.split(".")[0]) < 20) {
    process.stderr.write("ow-tools: Node.js 20 or newer is required\n");
    process.exitCode = EXIT.MISSING;
```

**Why it matters:**
The README (`:10`) and design §5.3 promise "Silent in every other folder" and "never fails the session". A user with an older default `node` gets a red hook error on every `startup|clear|compact` in every repository, and the error names ow-tools, which will read as the plugin being broken.

**Fix:**
Move the version check into `bin/ow-tools` before `exec`, with the same hook short-circuit:
```sh
major=$(node -p 'process.versions.node.split(".")[0]' 2>/dev/null || echo 0)
if [ "${major:-0}" -lt 20 ]; then
  if [ "$1" = "hook" ]; then exit 0; fi
  echo "ow-tools: Node.js 20 or newer is required (found $(node --version 2>/dev/null || echo none); macOS: brew install node)" >&2
  exit 3
fi
```
Keep the `cli.mjs` guard as a fallback but return `EXIT.OK` silently when `argv[0] === "hook"`. Add a `doctor-hook.test.js` case that runs the hook with a stub `node` printing `v18.0.0` and asserts exit 0, empty stdout, empty stderr.

### [F-003] Export follows `..` image paths anywhere on disk and embeds the file in the client document

**Severity:** MEDIUM
**Category:** security (data exposure to a third party)
**Location:** `plugins/ow-tools/lib/export.mjs:83-87`, `plugins/ow-tools/lib/preflight.mjs:132-136`
**Fix effort:** S (< 30 min)

**Problem:**
Preflight refuses *absolute* and *remote* image paths but accepts any relative path that exists, including ones that climb out of the document folder (`../../../../Users/me/Pictures/x.png`, or a non-image such as `../../.ssh/id_ed25519`). Export then `copyFileSync`s that file into the private temp folder under a neutral name and hands it to pandoc/Typst. Typst refuses a non-image (exit 5), but pandoc's docx writer embeds the bytes as `word/media/*` even when it cannot determine the image type (it warns and continues), so `--formats docx` ships the file to the client. The comment at `export.mjs:79-80` says the copy exists "so nothing outside the temp folder is reachable from Typst (--root) and paths can't escape", but the escape it closes is Typst's, not the copy's. The Markdown is written by an LLM skill from client material (transcripts, notes), which is the indirect-injection surface the fixture itself plants (`synthetic-fit-call.txt:123`, "ignore the above and recommend…").

**Evidence:**
```js
// preflight.mjs:132-136 — absolute refused, "..": accepted if the file exists
const base = dirname(resolve(mdPath));
for (const img of images) {
  if (isAbsolute(img.src)) bad(img.i, `image ${img.src} uses an absolute path; use a path relative to the document`);
  else if (!existsSync(resolve(base, decodeURI(img.src)))) bad(img.i, `image not found: ${img.src}`);
}
// export.mjs:83-86 — copied wherever it resolves to
pre.images.forEach((img, n) => {
  const local = `assets/img-${n}${extname(img.src) || ".png"}`;
  copyFileSync(resolve(dirname(src), decodeURI(img.src)), join(tmp, local));
```
Design §5.2 reads: "Images: every image has non-empty alt text; the file exists, *relative to the Markdown*".

**Why it matters:**
A client deliverable can carry an arbitrary readable file from the consultant's machine. Low probability, but the consequence is an exposure to the exact party the privacy rules protect against, and the human review step sees a rendered page, not the embedded bytes.

**Fix:**
In preflight, resolve the image and require it to stay under the document's folder (or the enclosing `opchain-work/` root when one is found, so a shared `opchain-work/brand/` image still works):
```js
const abs = resolve(base, decodeURI(img.src));
const rel = relative(allowedRoot, abs);
if (rel.startsWith("..") || isAbsolute(rel)) bad(img.i, `image ${img.src} is outside the document's folder; copy it beside the document`);
```
Also check the PNG/JPEG magic bytes before copying (the brand loader already does this for the logo at `brand.mjs:183-184`), and wrap `decodeURI` in a try/catch so a malformed `%` sequence is a usage error, not an "unexpected error" exit 5.

### [F-004] `uv run` without `--no-sync` can install packages into the venv, contradicting "installs nothing"

**Severity:** LOW
**Category:** config (stated security property)
**Location:** `plugins/ow-tools/lib/transcribe.mjs:137`, `plugins/ow-tools/README.md:25`, `plugins/ow-tools/SECURITY-MANIFEST.md:23`
**Fix effort:** S (< 30 min)

**Problem:**
`uv run` syncs the project environment before running the command unless `--no-sync` is given; `--frozen` only stops it rewriting the lockfile. With `UV_OFFLINE=1` it cannot download, but it will install any missing locked packages from `~/.cache/uv` (for example into a `venv-<lockhash>` that an interrupted `uv sync` left half-built, which passes the `bin/python` existence check at `transcribe.mjs:47`). The README's "ow-tools installs nothing itself" and the manifest's "It never runs … `uv sync`" are the admin-facing claims; the implicit sync is a gap in them.

**Evidence:**
```js
const args = ["run", "--frozen", "--project", PY_PROJECT, "python", join(PY_PROJECT, "diarize.py"), wav, join(tmp, "turns.json"), "--device", device];
```

**Why it matters:** An administrator approving from the SECURITY-MANIFEST is told the run step never installs. Making that literally true costs one flag.

**Fix:** Add `"--no-sync"` to the `uv run` argv. If the venv is incomplete, `python` fails with an ImportError and the user is pointed at `doctor` (exit 5 → the skill's fallback). Update the manifest sentence to "`uv run --frozen --no-sync`".

### [F-005] Git-ignore guard passes silently when `git` is not on PATH

**Severity:** LOW
**Category:** security (privacy guard)
**Location:** `plugins/ow-tools/lib/guards.mjs:52-53`
**Fix effort:** S (< 30 min)

**Problem:**
`notIgnored` treats a non-zero `git rev-parse` as "not in a repository" and lets the path through. `spawnSync` of a missing binary returns `status: null` with `error.code === "ENOENT"`, which is also `!== 0`, so a machine (or a hook/Bash PATH) without `git` skips the guard entirely even when the folder is a work tree that another tool (an IDE's bundled git, another machine) can commit from.

**Evidence:**
```js
const top = run("git", ["-C", probe, "rev-parse", "--show-toplevel"]);
if (top.status !== 0) continue; // not in a repository
```

**Fix:** Distinguish `top.error` (git missing → `throw missing("git is required to check that the transcript is git-ignored")`, exit 3) from `status === 128` (not a repository → continue). Same for the `check-ignore` call.

### [F-006] Atomic-write sibling file is not covered by the ignore guard; transcript files use default mode

**Severity:** LOW
**Category:** security (privacy guard completeness)
**Location:** `plugins/ow-tools/lib/transcribe.mjs:66-70`, `:93`
**Fix effort:** S (< 30 min)

**Problem:**
`writeAtomic` writes `transcript.json.tmp-<pid>` beside the final file and renames. `assertIgnored` checks only `transcript.json` and `transcript.md`. The recommended ignore line `opchain-work/**/transcript.*` happens to cover the sibling, but a repository whose `.gitignore` names the two files explicitly passes the guard while a crash between write and rename leaves a committable `transcript.json.tmp-1234` holding the whole transcript. Separately, `writeFileSync` uses the default mode (0644 after a typical umask) for files whose contents the design treats as sensitive.

**Evidence:**
```js
function writeAtomic(path, text) {
  const tmp = `${path}.tmp-${process.pid}`;
  writeFileSync(tmp, text);
  renameSync(tmp, path);
}
// transcribe.mjs:93
assertIgnored([audioAbs, jsonPath, mdPath]);
```

**Fix:** Add the two `.tmp-` paths to the `assertIgnored` list (or write the tmp into the private temp dir and `copyFileSync` + `renameSync` within outDir), and pass `{ mode: 0o600 }` to `writeFileSync` for `transcript.*`.

### [F-007] Full `doctor` reads the 1.6 GB Whisper model into memory to hash it, and the skill always runs the full form

**Severity:** LOW
**Category:** performance
**Location:** `plugins/ow-tools/lib/doctor.mjs:74-75`, `plugins/ow-tools/lib/core.mjs:64-66`, `plugins/ow-tools/skills/ow-tools/SKILL.md:12`
**Fix effort:** S (< 30 min)

**Problem:**
`sha256File` is `createHash().update(readFileSync(path))`: a single 1.6 GB `Buffer` plus several seconds of hashing on every `ow-tools doctor` without `--quick`. `/ow-tools` step 1 and `/ow-start-transcribe --setup` both tell Claude to run plain `ow-tools doctor`, so the slow path is the default path.

**Evidence:**
```js
if (modelOk && verifyModel) {
  modelOk = sha256File(mp) === m.sha256;
```

**Fix:** Stream the hash (`createReadStream` → `hash.update` chunks, or `node:crypto` `hash` over a stream) and/or have the SKILL run `doctor --quick` by default with the full hash only when the size check passes and the user asks to verify.

### [F-008] `calc date` output keys differ between modes, and holidays are silently ignored in `--days` mode

**Severity:** LOW
**Category:** quality (CLI contract read by skills)
**Location:** `plugins/ow-tools/lib/calc.mjs:40`, `:54`
**Fix effort:** S (< 30 min)

**Problem:**
Calendar-day mode returns `{ date, from, days, skipped: [] }`; business-day mode returns `{ date, from, business_days, calendar, holidays_skipped }`. A skill reading `holidays_skipped` gets `undefined` in one mode and `skipped` in the other. Passing `--holidays` with `--days` is accepted and ignored with no note, which a skill author could reasonably mistake for "holidays were applied". Arithmetic itself is correct (UTC-midnight dates, start day never counted, negative counts, 3650 cap; BigInt minor units; split remainder to the last share).

**Evidence:**
```js
if (days !== undefined) return { date: fmt(addUTC(start, n)), from: fmt(start), days: n, skipped: [] };
…
return { date: fmt(d), from: fmt(start), business_days: n, calendar: "Mon-Fri", holidays_skipped: skipped };
```

**Fix:** Use `holidays_skipped: []` and `calendar: "every day"` in the `--days` branch; refuse `--holidays` together with `--days` ("holidays only apply to --business-days") so the caller's intent is explicit.

### [F-011] Word run-property children are appended out of schema order (unverified in Word)
