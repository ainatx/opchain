## Executive Summary

Round 3 holds up. The five changes do what they claim, and none reopens an earlier finding:

1. **Capture's DNS pinning closes the rebinding and "name that points at loopback" gaps.** Each allowed host is resolved once before launch, any loopback, unspecified or link-local answer refuses the plan (mixed answers, AAAA-only `::1`, IPv4-mapped / NAT64 / 6to4 loopback, a CNAME chain ending at loopback, `0.0.0.0` and `169.254.169.254` all refused), and Chrome gets `MAP <host> <checked address>` for each name plus `MAP * ~NOTFOUND`. Chrome therefore never resolves an allowed name itself, so there is no window between the check and the connection. The lookup is a dynamic `import("node:dns")` inside capture only; the static fence test pins that, the manifest's Network row and `help network` both name it.
2. **Killed-run cleanup.** SIGINT, SIGTERM and SIGHUP close the browser and wipe a production session before exit; a production run writes `.ow-tools-production-pending` before launch and removes it only after a wipe, so SIGKILL, SIGQUIT, SIGUSR2, SIGALRM or an uncaught exception all leave the marker and the next run on the profile wipes first. Production runs also start wiped, and the session-adjacent stores (`Device Bound Sessions`, `Account Web Data`, `Login Data For Account`, `Reporting and NEL`, `Trust Tokens`) are on the wipe list. Real Chrome, success and failure: no session or session-adjacent store left. This closes SA-019 / F-025.
3. **pandoc metadata.** `yaml_metadata_block` is off in both readers, and the AST walk now covers the whole document, `meta` included. YAML `abstract`/`title` images, a `%` title block, a multi-line image, raw `\includegraphics`, a math `\includegraphics`, and a local-file link were tried for pdf, docx and pptx, both with the real preflight and with a deliberately blind one (the `deps.preflight` seam): nothing outside the document folder reached an output. `raw_attribute`, `raw_tex` and `pandoc_title_block` are off in pandoc 3.12.1's `gfm`; Typst's `--root` still confines the PDF.
4. **Secret-field detection.** The stem rule plus `aria-label` and `placeholder` catch every English variant I tried (`smsOtp`, `mfaToken`, `verifyCode`, `recovery_code`, `cardCvc`, `privateKey`, `Your PIN`, `CVV2`, …) with no false positive on 20 ordinary names (`footprint`, `passenger`, `secretary`, `options`, …).
5. **OSV partial answers and CVSS.** A missing reply, a `next_page_token`, a non-array `vulns`, an unreadable id or a missing `results` all make the package and the file summary **attention**, never OK. The 3.1 Roundup now matches the specification on 14 published vectors; CVSS 4.0 or malformed vectors are `unknown`, which is never OK; a `MAL-` entry stays critical whatever severity it also names.

## New findings

### [SA-020] Capture host names reach `--host-resolver-rules` unvalidated (`,` and `*` pass)

**Risk:** LOW · **Category:** T (argument grammar) · **Scope:** `plugins/ow-tools/lib/capture.mjs:149-166` (`origin()`), `:364-367` (`hostRules`) · **Fix effort:** S

**Problem:** `origin()` accepts any host the WHATWG URL parser accepts. That parser forbids whitespace (so no new rule keyword can be followed by a pattern) but allows `,`, `*`, `!`, `;`, `=`, `'` and `~`. `hostRules` writes the host straight into a comma-separated grammar. With a name that resolves (a wildcard DNS zone, or a resolver search domain), `https://a.example.com,exclude` produces `MAP a.example.com,exclude <addr>`, which Chrome splits into a broken `MAP` and a valid `EXCLUDE <addr>`; `https://*.example.com` produces a wildcard `MAP`, and a host of `*` maps every name to the checked address ahead of the `NOTFOUND` catch-all.

**Impact bound:** every outcome routes only to an address that `pinOrigins` checked (never loopback, unspecified or link-local), and the Fetch guard blocks any request whose origin isn't listed. The worst case is that non-Fetch traffic (a service worker, a WebSocket) on an allowed page can reach other host names at the checked address, or that a later-listed origin is routed to an earlier wildcard's address.

**Reproduction (`poc15-hostrules.mjs`, stub resolver):** `readPlan` accepts all of the hosts above, and `hostRules` emits them verbatim, for example `--host-resolver-rules=MAP * 203.0.113.5 , MAP * ~NOTFOUND`.

**Remediation:** in `origin()`, require an LDH host name (the same `HOST` pattern `health.mjs:18` uses: labels `[a-z0-9-]`, alphabetic TLD) or an IP literal, and refuse anything else with `plan-invalid`. That makes the rule string safe by construction. Add the plants above to `capture.test.js`.

### [SA-021] A second run on the same profile removes a running production run's pending-wipe marker

**Risk:** LOW · **Category:** I (session at rest; concurrency) · **Scope:** `plugins/ow-tools/lib/capture.mjs:650-657` · **Fix effort:** S

**Problem:** the start of every run does `cleanTempState` (which deletes Chrome's `SingletonLock`), wipes if the marker exists, then (non-production) `rmSync(pending)`. Nothing stops two runs on one workstream profile at once. If run B starts while production run A is in progress, B wipes A's live session (fail-safe) and removes A's marker; if A is then killed outright, the session A writes afterwards survives the next run. B also lets a second Chrome start on a profile that is in use.

**Reproduction (`poc17-concurrent.mjs`, fake browser, fence on):** A (production) running → marker present; B (uat, same profile) runs (exit 5) → marker gone; A SIGKILLed → no marker, so the next run won't wipe.

**Remediation:** take an exclusive per-profile run lock before any clean, wipe or marker step (for example `openSync(join(profileDir, ".ow-tools-run.lock"), "wx")` holding the pid, taken over only when that pid is dead) and refuse a concurrent run with a new reason `profile-in-use` (add it to design §14.3).

### [SA-022] The secret-field name rule is English-and-ASCII only

**Risk:** LOW (heuristic backstop) · **Category:** I · **Scope:** `plugins/ow-tools/lib/capture.mjs:47-95` (`nameWords`, `secretName`) · **Fix effort:** S

**Problem:** misses `contraseña` (the `ñ` is dropped before the `contrasena` stem is matched), `Kennwort`, `senha`, `wachtwoord`, `lösenord`, `salasana`, `hasło`, `пароль`, `パスワード`, leetspeak (`p@ssword`, `pa55word`), and descriptive placeholders ("Enter the code we texted you"). No false positive was found. The primary signals, `type=password` and `autocomplete` (`current-password`, `one-time-code`, `cc-*`), are language-independent and still refuse, and a plan value that looks like a credential is refused whatever the field, so a miss means ow-tools types screened test data into an OTP-style field, not a credential.

**Remediation:** fold accents first (`normalize("NFD").replace(/\p{M}/gu, "")`), add a short multilingual stem list (kennwort, senha, wachtwoord, losenord, salasana, haslo, and the Cyrillic, Japanese, Korean and Chinese words for password), and add `["code", "sent"|"texted"|"emailed"]` sequences. Keep the design's wording to "names in English and common languages".
