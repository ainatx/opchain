## Executive Summary

Round 2 closes everything the round-1 posture report raised. The three MEDIUMs are fixed and each is backed by a test and an independent PoC:

- **SA-010 (image containment):** export now lists the images **pandoc itself** will read (its AST) and refuses anything that is not one of the files ow-tools copied into the temp folder; preflight also refuses, by line, any image not written as `![alt](file)`. All three round-1 bypass forms, plus HTML `<img>`, raw-HTML blocks, data URIs and a reference-definition that points outside, are now refused. Nothing I could construct put an outside file into a PPTX or DOCX.
- **SA-011 (capture profile at rest):** per the owner's 2026-10-17 decision, `--use-mock-keychain` and `--password-store=basic` are gone, so the cookie key now comes from the real macOS Keychain, and a production run wipes cookies and all site storage afterwards. A cookie written by a run no longer decrypts with the old fixed key (`ERR_OSSL_BAD_DECRYPT`); a production run leaves no `Cookies`, `Network`, `Local Storage`, `Session Storage`, `IndexedDB`, `Service Worker`, `Login Data`, `History` or `Sessions`, on both the success and the failure path.
- **SA-012 (fail-open advisories):** an advisory that can't be rated is now `attention`, `MAL-*` and malicious-package entries are `critical`, CVSS-vector-only advisories are scored, a failed detail fetch is `attention`, and ids past the 200th are reported `not rated`, never OK.

Every round-1 LOW is closed too (closure table below), including the socket-timing and unfenced-test gap (F-016): the `[CHECKED]` guard now fires on the `socket` event before any byte is flushed, and the in-process stub suites run under a loopback fence that asserts zero non-loopback attempts.

**The `.bugcheck.json` secrets exception** the Generator added for the posture report's quoted key header is correct: one exact path, digest-pinned (`sha256:6686a9b9…520d00`, which matches the file), in the `secrets` list only. The verifier rejects a stale digest, so the report can't drift under the exception. The diff audit holds no key-shaped string and was given no exception.

**One new LOW (SA-019):** a production capture killed by SIGKILL skips the `finally`, so its session is not wiped until the next production run on that profile — the known "SIGKILL skips the finally" residual, now reaching the production session. SA-011's fix means that leftover is keychain-encrypted at rest, not the freely-decryptable blob it was in round 1, so the exposure is small. A start-of-run `wipeSession` for production profiles (mirroring the F-023 start-of-run cache clean) would close it. A few session-adjacent files (`Device Bound Sessions`, `Account Web Data`, `Login Data For Account`, `Reporting and NEL`) are also left by the production wipe; none is a usable session without the wiped cookie.

**Re-ratings (unchanged from round 1, now reflected in design §8):** SA-001 HIGH (carried; impact widened by 1.1.0, likelihood unchanged; Sprint 5), SA-004 MEDIUM (carried; Sprint 5), SA-009 LOW, F-011 LOW.

**Counts, round 2:** CRITICAL 0 · HIGH 0 · MEDIUM 0 introduced-and-open · LOW 1 new (SA-019). Carried owner-accepted residuals: SA-001 HIGH, SA-004 MEDIUM, SA-009 LOW, F-011 LOW, and the capture-background-traffic residual.

## New finding

### [SA-019] A production capture killed by SIGKILL leaves its session until the next production run; a few session-adjacent files survive the wipe

**Risk:** LOW · **Category:** I (session at rest) · **Scope:** `plugins/ow-tools/lib/capture.mjs:551,598-600`, `SESSION_STATE` · **Fix effort:** S

**Problem:** `wipeSession(profileDir)` runs in the `finally` of a production run, so SIGKILL (or a lost process) skips it, and the session persists until the next production run on that profile calls `wipeSession` again — the start of a run runs `cleanTempState` but not `wipeSession`. Separately, the wipe removes the primary stores but leaves `Default/Device Bound Sessions` (DBSC registrations), `Account Web Data`, `Login Data For Account` and `Reporting and NEL`.

Both are low: SA-011's fix means a leftover cookie is encrypted with the Keychain key, not a public constant, and DBSC state is useless without the (wiped) cookie. This is the same class as the already-accepted "SIGKILL/hook-timeout skips the finally" residual, now reaching the production session.

**Reproduction (`poc13c-kill.mjs`):** a production run SIGKILLed mid-step leaves `Default/Cookies` and `Default/Local Storage` on disk (Chrome still exits — the pipe closes).

**Remediation:** call `wipeSession(profileDir)` at the **start** of a run when `plan.environment === "production"`, mirroring the F-023 start-of-run `cleanTempState`; add `Device Bound Sessions`(+journal) to `SESSION_STATE`. Then a killed production run's session is gone by the next run even if that run is also killed before its `finally`.

**Verification:** `poc13c` after the fix leaves no `Cookies`/`Local Storage`; a unit test that pre-seeds those files in a production profile and runs capture asserts they're gone before the browser starts.
