# Security Posture Report — ow-tools 1.1.0 (Sprint T)

**Date:** 2026-10-16
**Scope:** threat-model delta for the six 1.1.0 parts, attack surface, privacy-claims re-check, supply chain, re-rating of the open residuals (practice level; line-level bugs are in the companion diff audit)
**Tier:** Standard (same frame as 2026-10-14: client-confidential material, one consultant per machine, code runs with the user's privileges). 1.1.0 adds two network-touching verbs and a browser profile that can hold a signed-in session on a client environment.
**Assessor:** oc-security-auditor skill (Sprint T contract deliverable 14, pass 1)
**Target:** `plugins/ow-tools/` on `claude/ow-tools-sprint-t` at `62af404f` (base `8aa3145b`), reviewed in a detached checkout. `npm ci --ignore-scripts`; `vitest run tests/ow-tools`: 12 files, 275 passed, 1 skipped. `gen-ow-tools-manifest.mjs --check` passes.
**Network rule:** no real traffic. Network checks used the injected stubs (`tests/ow-tools/health-stubs.mjs`) under a loopback-only fence. Browser checks used the installed Chrome 154 against a 127.0.0.1 page through the test-scoped origin path, with the plugin's own `--host-resolver-rules` map.
**Also read:** design §5.6–§5.10, §8, §12, §14 (`docs/plans/2026-10-09-ow-tools-design.md`), contract `sprints/release-2.1/ow-sprint-t/contract.md` § Security review, README, SECURITY-MANIFEST, both 2026-10-14 reports.

## Executive Summary

1.1.0 keeps the 1.0 discipline: Node built-ins only, argv-only spawns, strict readers for every new input (`health.yaml`, the capture plan, the hours ledger, `model.md`), stable refusal codes, and a manifest that matches the tree. The two network parts are carefully fenced:

- **health** routes every request through one module (`net.mjs`). That module resolves the name once, refuses blocked ranges, and connects to the checked address.
- **capture** drives Chrome over `--remote-debugging-pipe` with a fixed CDP allowlist that has no cookie, storage or `Runtime` method.

**The `agent: false` fix holds.** The bug briefly sent real requests during the build. Re-running health against the stubs under a fence that allows loopback sockets only produced **zero** DNS lookups and zero non-loopback connects. A control request with `agent: false` was caught by the same fence at `Agent.createConnection`. `net.mjs` has no other path to the network.

Three gaps need action before the PR leaves draft:

1. **SA-010 (MEDIUM): image confinement can be bypassed.** The fix for SA-003 / F-003 checks images with a single-line regex. Three ordinary CommonMark forms get past it: a shortcut reference (`![logo]` plus `[logo]: /path`), a title in single quotes, and brackets inside the alt text. pandoc then embeds the named file, from anywhere on disk, in the client `.pptx` (a new 1.1.0 sink) and `.docx`. That includes a non-image file, such as a key file. Design §8 and §12 and the README say this can't happen.
2. **SA-011 (MEDIUM): the capture profile is weaker at rest than a normal Chrome profile.** Chrome runs with `--use-mock-keychain`, so its cookies are encrypted with a fixed, public key. A session cookie from the profile was decrypted with no keychain prompt. Any process running as the user can therefore lift a live session on a client test environment, or on production when a decision is recorded. Design §8 accepts this, but only the Generator wrote that acceptance; the owner hasn't. This is also the main reason SA-001's impact grows in 1.1.0.
3. **SA-012 (MEDIUM): health's advisory check fails open.** An advisory whose severity ow-tools can't read is reported **OK**. That covers OSV's `MAL-` malicious-package entries, CVSS-only advisories, a failed detail fetch, and any id past the 200th.

**Re-ratings:**
- **SA-001 stays HIGH.** The likelihood is unchanged, and the impact now reaches live client sessions.
- **SA-004 stays MEDIUM.** Transcription is untouched.
- **SA-009 stays LOW.** The new printed fixes are package-manager lines only.
- **F-011 stays LOW.** The XLSX part order was checked against the schema; PPTX is covered by the owner's real-app check.

**Counts (new in 1.1.0):** CRITICAL 0 · HIGH 0 · MEDIUM 3 · LOW 5. Open residuals carried: SA-001 HIGH, SA-004 MEDIUM, SA-009 LOW, F-011 LOW.

**Grade: B−.** The engineering is careful. The grade is held back by a closed privacy control that is bypassable in ordinary Markdown, and by an at-rest weakness on the most sensitive new asset.

### Network fence evidence (C25)

- **Static:** only `lib/net.mjs` imports `node:https`, `node:tls` or `node:dns` (grep), and only `health.mjs` imports `net.mjs`, through a dynamic `import()` in `cli.mjs:192`. `cdp.mjs` imports `node:child_process` only.
- **Runtime (this review):** health with the full stub set under a preload that throws on any DNS lookup or non-loopback connect: 9 stub requests, 10 connector calls, **0 fence attempts**. Control: `https.request({ agent: false, createConnection })` → fence hit at `node:_http_agent` `Agent.createConnection` → `tls.connect('api.osv.dev')`. That is the build-time bug, and the shipped code no longer takes that path (`net.mjs:175-185`, no `agent` key).
- **Capture:** the browser's DNS is `MAP * ~NOTFOUND` except the plan's hosts (`capture.mjs:311`); `--no-proxy-server`. A Chrome run against 127.0.0.1 resolved nothing else.

## Pillar 3: Findings

### [SA-010] Image confinement is bypassed by ordinary CommonMark image forms; any local file reaches the client PPTX or DOCX

**Pillar:** Threat Model · **Risk:** MEDIUM (reopens SA-003 / F-003; new 1.1.0 sink) · **Category:** I, T (A01 path traversal / data exposure) · **Scope:** `plugins/ow-tools/lib/preflight.mjs:150-156,180-205`, `lib/export.mjs:179-184,213,224` · **Fix effort:** S–M

**Problem:** Preflight finds images with one per-line regex, `!\[([^\]]*)\]\(\s*<?([^)\s>]+)>?(?:\s+"[^"]*")?\s*\)`, and refuses only the `![a][b]` reference form. Three valid forms pandoc accepts never enter `images`, so they skip the containment, symlink and magic-byte checks:

- `![logo]` with a definition `[logo]: /any/path` (a shortcut or collapsed reference);
- `![alt](/any/path 'title')` (a single-quoted or parenthesised title);
- `![a [b] c](/any/path)` (balanced brackets in the alt text).

They are also never rewritten to `assets/img-N`. pandoc reads the absolute path (or a `..` chain from the temp folder) and embeds the bytes. Typst's `--root` saves the PDF; Word and PowerPoint get the file.

**Reproduction (this review, `poc3-image-bypass.mjs`, `poc3b-nonimage.mjs`):** a document in `doc/`, a PNG carrying a canary in a sibling folder:

```
nestedBrackets    pptx → exported; ppt/media/image1.png; canary embedded=true
singleQuoteTitle  docx → exported; word/media/rId11.png; canary embedded=true
shortcutRef       pptx → exported; ppt/media/image1.png; canary embedded=true
```

A text file starting `-----BEGIN OPENSSH PRIVATE KEY-----`, referenced as `![key](/abs/id_ed25519 'x')`, gave `pptx exported; canary hits: 1` and `docx exported; canary hits: 1`. The PDF failed in Typst. Every result was exit 0 with "images confined" in `checked`.

**Remediation:** Enumerate images the way pandoc does, not by regex. Run the same reader once to JSON:

```
pandoc <tmp>/doc.md -f <PANDOC_FROM or PANDOC_DECK_FROM> -t json
```

Walk every `Image` node, and refuse unless its target is exactly one of the `assets/img-N.<type>` names ow-tools wrote. Then pass `--resource-path` to the `assets/` folder only. Keep the regex check for its line-numbered messages.

Short of that:

1. Refuse any line that holds `![` and isn't fully matched by the inline-image regex.
2. Refuse every link-reference definition (`^\s{0,3}\[[^\]]+\]:\s`).
3. After the copy, refuse if pandoc's `--extract-media` listing (or the unzipped `media/` folder) holds more files than `pre.images.length` (+1 for the logo).

Add plants for the three forms to `brand-preflight.test.js` and `xlsx-pptx.test.js`.

**Verification:** each plant exits 4 `preflight` naming the line; the unzipped PPTX and DOCX `media/` folders hold exactly the copied images.

### [SA-011] The capture profile stores client sessions in a form any same-user process can decrypt

**Pillar:** Threat Model · **Risk:** MEDIUM · **Category:** I, E (A02 cryptographic storage / A07 session) · **Scope:** `plugins/ow-tools/lib/capture.mjs:308-309,318-321,503,549`, design §8 "The capture profile" and Known residuals · **Fix effort:** S

**Problem:** Chrome is launched with `--use-mock-keychain` (and `--password-store=basic`). Its cookie key is then derived from a fixed built-in password instead of a login-keychain item, so the `Cookies` database is readable by any process running as the user. That includes an npm install script in an unrelated repo, a prompt-injected Bash call, or a compromised ow-tools update (SA-001), and none of them sees a keychain prompt. SPA tokens in Local Storage are plaintext in every Chrome profile, and they persist here too, along with History and Service Worker CacheStorage.

The profile persists across runs by default, including `environment: production` runs with a recorded decision. The design's own spike explains why persistence is rarely needed: `--sign-in` already runs the steps in the same session, because session-only cookies don't survive a restart.

**Reproduction (`poc10-cookie.mjs`):** a 127.0.0.1 page sets `session=ZQSESSION-TOKEN-4242; Max-Age=3600`. After `capture`, `sqlite3 …/Default/Cookies` gave a `v10` blob. AES-128-CBC with `PBKDF2("mock_password","saltysalt",1003)` produced `decrypted contains token: true`.

**Remediation (pick one; the first is cheap):**

1. Use a throwaway `--user-data-dir` (`mkdtemp`, 0700, removed in `finally`) for `--sign-in` runs and for every `environment: production` run. Keep a persistent profile only for non-production headless re-runs, and print in the JSON that a persistent session was kept and where.
2. Drop `--use-mock-keychain` on macOS for persistent profiles, so Chrome keeps its key in the login keychain. Accept one keychain prompt on first use; the headless re-run uses the stored item.
3. If the owner keeps the design as is: record the acceptance in the PR. Reword §8 and the README from "folder permissions only" to "any program running as you can read the signed-in session; delete the profile when the engagement ends". Add the profile to the `ow-handoff` checklist with a date.

**Verification:** a production plan leaves no `capture/<id>/Default/Cookies` after the run; or, for option 2, the decrypt PoC fails without a keychain prompt.

### [SA-012] health reports an advisory it couldn't rate as OK (fails open)

**Pillar:** Threat Model · **Risk:** MEDIUM · **Category:** T (integrity of a security result; A09-adjacent) · **Scope:** `plugins/ow-tools/lib/health.mjs:279-297` · **Fix effort:** S

**Problem:** Severity is read only from `database_specific.severity`. Anything else becomes `"unknown"`, whose `SEVERITY.indexOf` is −1, so `top` is false and the package is reported **OK — "listed below the threshold"**. That happens in four cases:

- OSV `MAL-*` malicious-package entries, which carry no such field;
- CVSS-only advisories (`severity: [{type: "CVSS_V3", …}]`);
- a failed or non-200 detail fetch;
- every id past the 200-id cap.

ow-care's monthly check would tell a client "OK" for a package OSV lists as malware.

**Reproduction (`poc7-unknown-severity.mjs`, stub routes):**

```
OK  package-lock.json: left-pad@1.3.0 — listed below the threshold: GHSA-cvss-only (unknown)
OK  package-lock.json: lodash@4.17.21 — listed below the threshold: MAL-2026-0001 (unknown)
```

**Remediation:**

- Treat `unknown` as at or above every threshold, giving `attention` with "severity not available".
- Map `MAL-*` ids, or any entry with `database_specific["malicious-packages-origins"]`, to `critical`.
- Read `severity[].score` (a CVSS vector) when `database_specific.severity` is absent; at minimum report `unknown` as attention.
- Report ids beyond the cap as `not checked (more than 200 advisories)` instead of rating them.

**Verification:** the PoC's two rows become `attention`; a stub returning 201 ids yields one `not checked` row.

### [SA-013] capture's "never loopback" rule accepts loopback origins

**Pillar:** Threat Model · **Risk:** LOW · **Category:** T (policy bypass) · **Scope:** `plugins/ow-tools/lib/capture.mjs:82-96` · **Fix effort:** S

**Problem:** The check compares the hostname with `localhost`, `*.localhost`, `::1` and `127.*` / `0.*` literally. It accepts `https://localhost.`, `https://foo.localhost.` (Chrome treats both as loopback), `https://[::]` (connects locally) and `https://[::ffff:7f00:1]`. Names that resolve to 127.0.0.1 (for example `lvh.me`) are DNS-dependent and can't be caught without resolving.

**Reproduction (`poc2-addr-origin.mjs`):** `readPlan` returns `ACCEPTED` for each of the four.

**Remediation:** Strip one trailing dot before comparing. Run IP literals through `net.mjs`'s `blockedAddress` and refuse any loopback, unspecified or IPv4-mapped-loopback form. Add the four plants to `capture.test.js`.

**Verification:** each plant exits 4 `plan-invalid`.

### [SA-014] npm organisation-private packages hosted on registry.npmjs.org are classed public and sent

**Pillar:** Threat Model · **Risk:** LOW · **Category:** I (dependency-name disclosure) · **Scope:** `plugins/ow-tools/lib/lockfiles.mjs:11,15-24`, `lib/health.mjs:239-248`, README Privacy · **Fix effort:** S

**Problem:** A paid-org private package (`@acme/billing-core`) resolves to `https://registry.npmjs.org/@acme/...`, so `sourceOfUrl` returns `public`. Its name and version go to `api.osv.dev`, and its name goes to `registry.npmjs.org`, unless `health.yaml` lists `@acme` in `private_scopes`. The README's "Packages from a private registry or a private scope are never sent" reads as automatic.

**Remediation:** Hold the project's own scope by default: the scope of `package.json`'s `name`, and of every workspace `name`. Say in §5.8 and the README that org-private packages on the public registry need `private_scopes`. ow-care's `health.yaml` writer (Sprint 4b) should fill it in.

**Verification:** a fixture with `name: "@acme/app"` and a `@acme/x` dependency resolved on registry.npmjs.org → `not checked (private scope)`; the OSV stub sees no `@acme/` name.

### [SA-015] Address rules miss a few special-purpose ranges

**Pillar:** Threat Model · **Risk:** LOW · **Category:** I (SSRF hardening) · **Scope:** `plugins/ow-tools/lib/net.mjs:35-82` · **Fix effort:** S

**Problem:** `blockedAddress` returns false for:

- `fec0::/10` (deprecated site-local, still routed on some networks);
- `::ffff:0:0/96` (IPv4-translated, for example `::ffff:0:7f00:1`);
- Teredo `2001::/32` (embeds an obfuscated IPv4);
- `100::/64` (discard);
- `2001:10::/28`;
- `192.88.99.0/24`.

The local-use NAT64 `64:ff9b:1::/48` is only checked for its embedded IPv4. Exploitation needs a DNS answer in these ranges and a network that routes them, so this is low.

**Reproduction (`poc2-addr-origin.mjs`):** `blockedAddress("fec0::1") === false`, `blockedAddress("::ffff:0:7f00:1") === false`.

**Remediation:** Invert to an allowlist: refuse any IPv6 outside `2000::/3` except documented public use, plus explicit blocks for Teredo and the translated prefix. For IPv4, add `192.88.99/24`.

**Verification:** extend the C25(d) table in `health.test.js:197-210`.

### [SA-017] A failed export leaves unbranded, world-readable deliverables in `export/` and no record

**Pillar:** Threat Model · **Risk:** LOW · **Category:** I, R · **Scope:** `plugins/ow-tools/lib/export.mjs:161-165,205-229,232-238`, `lib/pptx.mjs:23-79,192` · **Fix effort:** S

**Problem:** Each format is written straight to its final path. pandoc and Typst write at the default 0644, and `chmod 0600` plus `recordExport` run only after every format succeeds. When a later step fails, three things go wrong:

- the earlier outputs stay at 0644;
- a PPTX that fails `brandPptx` stays without its banner (for example "CONFIDENTIAL"), replacing the previous good one;
- no record is written.

`deckChecks` doesn't refuse thematic breaks (`***`, `---`, `___`), which pandoc turns into extra slides. That is an easy way to reach the slide-count failure.

**Reproduction:** a deck with a banner and `***` inside one slide, `--formats pdf,pptx` → `exit 5 pandoc made 2 slides from 1 slide headings`. Afterwards `export/deck.pdf` and `export/deck.pptx` are present at mode 644, `deck.export.json` is absent, and the banner is in no slide.

**Remediation:** Build every format inside the 0700 temp folder, then `chmod 0600` and rename into `export/` only after all formats and checks pass. Add thematic breaks to the deck rules.

**Verification:** the same reproduction leaves `export/` unchanged (or exactly as before the run).

### [SA-018] XLSX export neither honours nor refuses `ow:internal` markers in `model.md`

**Pillar:** Compliance (design claims) · **Risk:** LOW · **Category:** I · **Scope:** `plugins/ow-tools/lib/xlsx.mjs:99-151,222-247` · **Fix effort:** S

**Problem:** `model.md` is Markdown written by the same skills that use the internal markers. `parseModel` ignores comments, so a `## Sheet:` section wrapped in `<!-- ow:internal -->` … `<!-- ow:end-internal -->` is applied. Every CSV in the folder becomes a sheet whatever the model says. Markdown export refuses any stray "internal" comment (the F-001 lesson); xlsx is silent.

**Reproduction:** a `Margin.csv` (unit cost 61.50) plus a `model.md` that wraps `## Sheet: Margin` in internal markers → `exported sheets: [ 'Costs', 'Margin' ]`, and `61.50` is in the workbook.

**Remediation:**

- Refuse (exit 4 `preflight`, naming the line) any `model.md` comment that mentions "internal".
- Refuse any CSV whose name starts with `internal`, or require every CSV to be named in `model.md` (an unnamed CSV refuses).
- Say in §5.9 that every CSV in the folder ships.

**Verification:** the reproduction exits 4.
