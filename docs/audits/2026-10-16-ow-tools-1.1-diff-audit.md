## Findings (ordered by severity, then fix effort)

### [F-012] Preflight's image regex misses three CommonMark forms; pandoc embeds any local file in the PPTX and DOCX

**Severity:** MEDIUM
**Category:** security (data exposure to a third party; closed control bypassed)
**Location:** `plugins/ow-tools/lib/preflight.mjs:150-156`, `:180-205`; `plugins/ow-tools/lib/export.mjs:179-184`, `:213`, `:224`
**Fix effort:** S–M

**Problem:**
Images are found with one per-line regex, and only `![a][b]` is refused as a reference form. Three valid forms never enter `pre.images`:

- a shortcut or collapsed reference, `![logo]` with `[logo]: /path`;
- a title in single quotes or parentheses;
- balanced brackets in the alt text.

Because they never enter `pre.images`, they are never confined, sniffed or rewritten to `assets/img-N`. pandoc (`-t docx`/`-t pptx`, `--resource-path tmp`) then reads the path as given, absolute or a `..` chain, and embeds the bytes. The comment at `export.mjs:168-172` ("Preflight has already confined each image") and contract C10 ("images confined") don't hold. pptx is the 1.1.0 sink.

**Evidence:**
```js
// preflight.mjs:150 — the only image extraction
for (const m of l.matchAll(/!\[([^\]]*)\]\(\s*<?([^)\s>]+)>?(?:\s+"[^"]*")?\s*\)/g)) {
// preflight.mjs:156 — only the full reference form is refused
if (/!\[[^\]]*\]\[[^\]]*\]/.test(l)) bad(i, "reference-style images are not supported; use ![alt](file)");
```
Reproduction (doc in `doc/`, canary PNG in a sibling folder; `poc3-image-bypass.mjs`):
```
nestedBrackets    pptx → exported; media=["ppt/media/image1.png"]; canary embedded=true
singleQuoteTitle  pptx → exported; media=["ppt/media/image1.png"]; canary embedded=true
shortcutRef       docx → exported; media=["word/media/rId11.png"]; canary embedded=true
```
`![key](/abs/id_ed25519 'x')` pointing at a fake OpenSSH key text file → `pptx exported; canary hits: 1`, `docx exported; canary hits: 1` (`poc3b-nonimage.mjs`). Exit 0, `checked` lists "alt text on every image".

**Why it matters:** This is the SA-003 / F-003 class, with a new deliverable type. The Markdown is skill-written from client material, the indirect-injection surface the design names. A key file or a personal document lands in a client deck with no warning.

**Fix:**
1. Authoritative enumeration: run `pandoc <tmp>/doc.md -f <reader> -t json` once, walk all `Image` nodes, and refuse unless each target is one of the copied `assets/img-N.<type>`. Then point `--resource-path` at `<tmp>/assets` only.
2. Belt and braces in preflight: refuse any line containing `![` that the inline regex doesn't fully consume, and refuse link-reference definitions (`^\s{0,3}\[[^\]]+\]:\s`).
3. Plants for all three forms in `brand-preflight.test.js` (pdf and docx) and `xlsx-pptx.test.js` (pptx), asserting exit 4 and that `media/` contains only the copied images.

### [F-013] An advisory with an unreadable severity is reported "OK"

**Severity:** MEDIUM
**Category:** security (fail-open security result)
**Location:** `plugins/ow-tools/lib/health.mjs:279-297`
**Fix effort:** S

**Problem:**
`severity` comes only from `database_specific.severity`. Anything else becomes `"unknown"`, and `SEVERITY.indexOf("unknown")` is −1, so `top` is false and the row is `OK — listed below the threshold`. That covers four cases:

- OSV `MAL-*` malicious-package entries;
- CVSS-only advisories;
- a failed or non-200 `GET /v1/vulns/<id>` (the `catch` at `:287-289`);
- every id past `slice(0, 200)` (`:279`).

**Evidence:**
```js
severity.set(id, s === "medium" ? "moderate" : SEVERITY.includes(s) ? s : "unknown");   // :286
const top = list.some((a) => SEVERITY.indexOf(a.severity) >= min);                       // :295
```
`poc7-unknown-severity.mjs` (stub routes):
```
OK  package-lock.json: left-pad@1.3.0 — listed below the threshold: GHSA-cvss-only (unknown)
OK  package-lock.json: lodash@4.17.21 — listed below the threshold: MAL-2026-0001 (unknown)
```

**Why it matters:** ow-care relays these rows to a client monthly. "OK" for a package OSV lists as malware, or for one whose rating fetch timed out, is the wrong direction to fail.

**Fix:**
- `unknown` → `attention` with "severity not available".
- An `id` matching `^MAL-` or `database_specific["malicious-packages-origins"]` → `critical`.
- Optionally derive a band from `severity[].score` (CVSS).
- Ids beyond 200 → one `not checked (more than 200 advisories; run a full audit)` row.
- Tests: the two PoC rows become `attention`, and 201 ids yield the `not checked` row.

### [F-014] Outputs are written in place before every format succeeds; a failure leaves unbranded, 0644 files and no record. Deck rules miss thematic breaks

**Severity:** LOW
**Category:** security (handling / repudiation)
**Location:** `plugins/ow-tools/lib/export.mjs:161-165`, `:205-229`, `:232-238`; `plugins/ow-tools/lib/pptx.mjs:23-79`, `:192`
**Fix effort:** S

**Problem:**
`target()` returns the final path. Typst and pandoc write there at the default mode, and `chmod 0600` plus `recordExport` run after `withTempDir` returns. When the PPTX branding check throws, the deck pandoc wrote stays in `export/` without its banner, replacing any previous good deck. The PDF written before it stays at 0644, and nothing is recorded (SA-007's purpose).

`deckChecks` doesn't refuse thematic breaks (`***`, `---`, `___`), which pandoc's pptx writer turns into new slides. That is a one-line way to reach the slide-count failure.

**Evidence:** A deck with banner `CONFIDENTIAL BANNER` and `***` inside one slide, `--formats pdf,pptx` gave:
```
exit 5 pandoc made 2 slides from 1 slide headings; …
deck.pdf present mode 644 · deck.pptx present mode 644 · deck.export.json absent · banner in pptx: 0
```

**Fix:** Write each output into the temp folder; after all formats pass, `chmod 0600` and `renameSync` into `export/` (or copy and rename when it's on another device), then record. Add `^\s{0,3}([-*_])(\s*\1){2,}\s*$` outside notes to the deck rules with a plant.

### [F-015] Capture's loopback refusal is a string match; four loopback origins pass

**Severity:** LOW
**Category:** security (policy bypass)
**Location:** `plugins/ow-tools/lib/capture.mjs:93-94`
**Fix effort:** S

**Problem / Evidence:**
```js
if (h === "localhost" || h.endsWith(".localhost") || /^\[?(::1|0:0:0:0:0:0:0:1)\]?$/.test(h) || /^(127|0)\./.test(h)) throw …
```
`readPlan` accepts `https://localhost.`, `https://foo.localhost.`, `https://[::]` and `https://[::ffff:7f00:1]` (`poc2-addr-origin.mjs`). Chrome treats the first two as loopback, and `[::]` connects locally.

**Fix:** Drop one trailing dot before the comparison. For IP-literal hosts, use `blockedAddress`'s loopback, unspecified and mapped forms (export a small `isLoopbackLiteral` from `net.mjs`). Add plants for the four.

### [F-016] The belt-and-braces socket check runs after the request is sent, and the stub suites run unfenced

**Severity:** LOW
**Category:** security (defence-in-depth / test safety)
**Location:** `plugins/ow-tools/lib/net.mjs:187-193`; `tests/ow-tools/health.test.js:90-160` (in-process stub runs)
**Fix effort:** S

**Problem:**
The `[CHECKED]` assertion is in the `response` handler, so if a future edit reintroduces an agent, the headers and the OSV POST body (package names) have already left before the check fires. The in-process stub tests don't run under `fence.mjs`. That is why the `agent: false` bug sent real requests during the build: the test caught it (`:157`), but only after the traffic.

**Fix:**
- Move the assertion to `req.on("socket", …)`, which fires before `ClientRequest` flushes, and `destroy` there.
- Run the in-process stub suites under a loopback-only preload: allow `net.Socket.connect` to `127.0.0.1` and throw on `dns.lookup` and any other host. This review's `loopfence.mjs` is 20 lines.

A regression then fails closed with zero bytes sent.

### [F-018] digest's `O_NOFOLLOW` guards the last path component only

**Severity:** LOW
**Category:** security (TOCTOU; claim precision)
**Location:** `plugins/ow-tools/lib/hash.mjs:11-13`; `plugins/ow-tools/lib/digest.mjs:64-71`; design §5.10
**Fix effort:** S

**Problem / Evidence:** After the lstat walk, a **directory** swapped for a symlink is followed, because `O_NOFOLLOW` applies only to the final component. `sha256File("tree/sub/f.txt", { noFollow: true })` with `tree/sub → ../outside` returned a hash, while a leaf symlink gave `ELOOP`. Impact is a wrong digest (the tool states it isn't tamper-evidence), but Sprint C's `build-packs` will pin with it.

**Fix:** Open each directory with `O_DIRECTORY|O_NOFOLLOW` and read files relative to it. Or, cheaper: after hashing, `realpathSync(join(root, p))` must equal `join(realRoot, p)`; refuse otherwise. Reword §5.10 to "a file or folder swapped …".

### [F-019] XLSX writer has no Excel limits: invalid workbooks and an unbounded row × column loop

**Severity:** LOW
**Category:** quality / availability
**Location:** `plugins/ow-tools/lib/xlsx.mjs:80`, `:289-297`, `:333-336`
**Fix effort:** S

**Problem / Evidence:** `CELL` accepts rows up to 9,999,999, and CSV width is unbounded. `A1048577` and `A9999999` are accepted and produce workbooks Excel can't open (`poc4-xlsx.mjs`: accepted, 2.8 KB). The output loop is `rows × cols`, so `XFD9999999` in `model.md` means about 1.6×10¹¹ iterations, a hang. A 10 MB CSV row of commas exceeds 16,384 columns.

**Fix:** Refuse a row above 1,048,576 or a column above 16,384 (`XFD`), both in `parseCell` and in CSV extents, with a usage error naming the line.
