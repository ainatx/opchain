## New finding

### [F-025] Production session not wiped on SIGKILL; a few session-adjacent files survive the wipe

**Severity:** LOW · **Category:** security (session at rest) · **Location:** `plugins/ow-tools/lib/capture.mjs:551,598-600`, `SESSION_STATE` (= posture SA-019)
**Problem:** `wipeSession` runs only in the `finally`, so a SIGKILLed production run leaves its session until the next production run on that profile; the start of a run runs `cleanTempState` but not `wipeSession`. The wipe also leaves `Device Bound Sessions`, `Account Web Data`, `Login Data For Account`, `Reporting and NEL`. Low because the leftover cookie is now Keychain-encrypted (SA-011) and DBSC is useless without it.
**Evidence:** `poc13c` — a production run SIGKILLed mid-step leaves `Default/Cookies` and `Default/Local Storage`.
**Fix:** run `wipeSession` at the start of a production run too (mirror the F-023 start-of-run `cleanTempState`); add `Device Bound Sessions`(+journal) to `SESSION_STATE`.
