## Findings

### S3-F001 — HIGH — A checkout path containing spaces turns the release-tag CLI into a silent successful no-op

**Category:** config / release verification. **Location:** `scripts/check-release-tag.mjs:481`; consumer at `scripts/release-sequence.mjs:151`. **Effort:** S. **Status:** open; newly reproduced here.

The CLI compares `import.meta.url` to an unescaped `file://${process.argv[1]}`. Under a checkout named `untagged release`, the actual module URL contains `%20`; the equality is false and the entire CLI body is skipped. Node exits 0 without checking catalog, seal, signature or tag existence. The post-tag release sequence treats that zero exit as success and reports `post-tag: 1 ok ... 0 FAILED` even when `v2.0.0` does not exist. A direct `--local --no-fetch --json` invocation also silently succeeds with a lightweight unsigned tag. The identical candidate in `untagged-release-control` returns the required failure.

Pre-tag catches missing JSON and fails, so the ordinary full sequence does not sail through both stages. This nevertheless disables the standalone signed pre-push/tag validation and the independent post-tag gate in a common filesystem layout. **The production deploy path is not proven bypassed**: it imports the checker function directly and the preview marker independently stopped our deploy probe. Remediation proposal only: use filesystem-safe entrypoint comparison (for example `pathToFileURL(resolve(process.argv[1])).href`) and regress both spaced-path pre/post-tag CLI behavior. No fix applied.

Evidence: logs 42–45 versus 49–52; original discovery saved in `first-run-failure.json`.

### S3-F002 — MEDIUM — Git Ops still instructs users to rely on the removed checkpoint/PreToolUse gate

**Category:** quality / cross-skill contract. **Location:** `skills/oc-git-ops/SKILL.md:240`, `:244`, `:249–258`, mirrored in `plugins/opchain/skills/oc-git-ops/SKILL.md`. **Effort:** S. **Status:** open; live contract contradiction.

The active skill says a checkpoint PASS is bound to `skill_state.verified_tree`, the plugin ships a `PreToolUse(Bash)` blocking hook, and plugin installation supplies real enforcement. The current Bug Check contract at `skills/oc-bug-check/SKILL.md:623–660` instead requires explicit Git enrollment and an immutable candidate receipt; the plugin `hooks/hooks.json` registers only SessionStart and Stop. An operator following Git Ops can install the plugin and believe enforcement is active without running `/oc-enroll`.

Actual enrolled-boundary probes work correctly: old checkpoint PASS did not authorize the bad commit. This finding is about shipped guidance and the enrollment path, not a failure of the new Git hook. Remediation proposal only: rewrite Git Ops around advisory skill checks plus explicit enrollment and actual candidate receipts, then regenerate its packaged copy. Do not restore the old checkpoint gate.
