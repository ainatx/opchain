# Data handling

Last reviewed: 2026-09-02

This document describes the data paths implemented by the opchain.dev Worker.
It is an engineering inventory, not a certification or legal opinion. The
public-facing summary is the [privacy page](https://opchain.dev/privacy).

## Stored data

| Data | Store / processor | Keying | Retention | Purpose |
|---|---|---|---|---|
| Email sign-up plus optional role, team size, project description, source, timestamp, and request id | Cloudflare KV | `lead:<sha256(email)>` | 365 days | Newsletter and install/download follow-up |
| Hosted MCP checkpoint JSON | Cloudflare KV | `mcp-checkpoint:<private-session-token>:<catalog-skill-id>` | 30 days from the latest write | Cross-session agent continuity |
| MCP checkpoint mutation limiter | Cloudflare Rate Limiting binding | Truncated IP hash | 60-second edge-local window | Abuse prevention; configured for 30 session creates or writes per IP and Cloudflare location |
| Email-submit counter | Cloudflare KV | `ratelimit:notify:<truncated-ip-hash>` | 60 seconds | Abuse prevention; 3 submits per IP/window |
| Public roadmap-request counter | Cloudflare KV | `ratelimit:roadmap-request:<truncated-ip-hash>` | 1 hour | Abuse prevention; 5 requests per IP/window |
| Roadmap vote lock | Cloudflare KV | `vote-lock:<issue>:<date>:<truncated-ip-hash>` | 25 hours | One vote per IP/day |
| Aggregate roadmap vote count | Cloudflare KV | `vote-count:<issue>` | Until the roadmap item is retired or manually deleted | Public prioritization total |
| Feature-rollout identifier | Browser cookie `oc_id` | Random UUID | 1 year | Stable feature-flag bucketing |
| Browser analytics consent and PostHog state | Browser local storage / PostHog | Browser-generated ids | Until browser reset or vendor retention applies | Optional page and interaction analytics |
| Feedback | Linear | Issue fields supplied by the user | Linear workspace retention | Triage and response |
| Community feature request | Public GitHub issue | GitHub issue | GitHub repository retention | Public roadmap intake |

Cloudflare Web Analytics also receives its cookieless pageview beacon. When
configured, the Worker emits PostHog events for downloads, feedback, and email
sign-ups. Those server-side events use an email hash or full SHA-256 IP-derived
identifier, not a raw email. Vendor retention applies to those identifiers;
they are separate from browser consent because they are operational events
generated by a submitted action.

## Hosted MCP constraints

- Clients call `create_checkpoint_session`; the service returns a random,
  HMAC-signed `sessionId`. Reads and writes reject syntactically valid tokens
  without a valid service signature. The token acts as a bearer secret;
  clients must not invent, log, or share it.
- Only skill ids in the published catalog may be used.
- A checkpoint is capped at 64 KiB; the full JSON-RPC request is capped at
  256 KiB and a batch at 25 messages.
- Session creates and checkpoint writes pass through a Cloudflare Rate Limiting
  binding configured for 30 mutations per IP and 60-second location-local
  window, and fail closed if that binding is unavailable. The platform limiter is intentionally
  permissive under near-simultaneous traffic and is an abuse control, not an
  exact accounting system. Checkpoints are stored with a 30-day TTL.
- Cloudflare KV limits repeated writes to the same checkpoint key to one per
  second. Clients should coalesce faster saves and retry a throttled write.
- Hosted HTTP requests reject any present `Origin` outside the explicit
  opchain allowlist before parsing, storage, or rate limiting. Native MCP
  clients that omit `Origin` remain supported.
- Checkpoints should contain workflow state only. Do not store credentials,
  secrets, health data, payment data, or other regulated data.

The v1.9 security migration resets and deletes every pre-v1.9 hosted
checkpoint because those records were not scoped by server-issued signed
sessions. Local on-disk skill checkpoints are a separate format and are
unaffected.

## Deletion and operational handling

Requests to delete an email record or an unexpired MCP checkpoint can be sent
to privacy@opchain.dev. A checkpoint request must include its skill id and
private session token so the operator can identify the KV key. The “Manage
privacy” footer action clears the browser consent choice, PostHog local-storage
keys, and the `oc_id` cookie.

Production secrets live in Cloudflare secret bindings and are never copied
into evidence bundles, checkpoints, logs, or this repository. Self-hosted
deployments use the same key prefixes and TTLs in the operator's own Cloudflare
account; configured feedback, roadmap, and analytics flows go to the external
services that operator selects. Production and staging use different
`MCP_SESSION_SIGNING_KEY` values so a token minted in one environment is
invalid in the other; rotating a key invalidates that environment's sessions.
