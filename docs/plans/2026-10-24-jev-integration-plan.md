## 1. Goal and constraints

**Goal.** One Jev use exists today (the prompt router, in shadow). Every further use should cost one JSON file and one gold set, not a second transport, a second redactor and a second eval harness. §2 builds that shared layer and proves it on three uses of different shape: a Choice-over-skills use that already runs (J1), a Noul the eval wants (J2), and a Noul the ow- family could use without touching its protocol (J9).

**Constraints, all of them hard.**

- **No API call without the owner's key.** `TYPESAFE_API_KEY` is read from the environment and never logged; every eval path accepts a canned fixture and refuses to run live without the key. Tests use fixtures only.
- **No edits to `skills-work/` protocol text.** J9 quotes `ow-protocol.md` §3d; it does not change it. A Jev reading of a file is a hint for the ow-tools add-on at most, never a rule in a skill.
- **ow- stays out of the plugin outputs** (`catalogs.json`: `plugin: null`). `jev-questions.json` ships in `plugins/opchain/hooks/` because the router already ships there; it names no ow- skill as a routing target.
- **Jev never decides on its own.** Every use produces a probability the caller thresholds, the way `route-dispatch.evaluate()` does, with the gold set saying what the threshold costs.
- **The router's measured numbers do not move in this PR.** `route-dispatch.cjs` keeps every export and every default; `route-spec.json` is unchanged, so no `SPEC_SCHEMA_VERSION` bump and no cache invalidation.

## 2. Shared client layer (this PR)

| Piece | Where | What it is |
|---|---|---|
| `jev-client.cjs` | `plugins/opchain/hooks/lib/jev-client.cjs` | Dependency-free CommonJS. The TypeSafe transport (`httpTransport`: bearer auth, pinned `jev-1.13.0`, one retry on 429/529, timeout, key never in an error), the test transport (`fixtureTransport`), the redactor (`redactSecrets`, `redactDeep`), `apiKeyFrom(env)`, `ask({ transport, state, questions })` returning `{ answers, usage, model, ms }`, and the answer readers `noul(answers, id)` / `choice(answers, id)`. `route-dispatch.cjs` requires it and re-exports the same names, so the hook and every existing test see no change. |
| `jev-uses.json` | `scripts/jev-uses.json` | The hand-written registry of Jev uses: id, name, status, kind, the question wording, what state the caller sends, which gold set proves it, and for J2 the per-skill steps. The only place a use's wording lives. |
| `jev-questions.json` | `plugins/opchain/hooks/jev-questions.json` | Generated by `gen-route-spec.mjs` from `jev-uses.json` plus the route spec (J1's gates, rules and `none` text come from the router's own constants; J2's skill options come from the spec's `displayName` and `index`). Sorted keys, tracked, drift-checked by `gen-route-spec --check` in `pretest`/`prebuild`, versioned with the spec. |
| `route-eval jev` | `scripts/route-eval.mjs` | `jev --list` prints the registry. `jev <use> [--gold f] [--fixture f] [--out f] [--report f] [--threshold 0.5] [--min-accuracy x]` scores a gold set: J1 rows go through `route()` with the shipped thresholds and allowlist (what the hook would do); Noul rows build the use's question from `jev-questions.json` and read the probability. Reports accuracy, precision/recall on the positive class, confusions, the lowest-margin rows, tokens and cost. Exit 2 without a key or fixture; exit 3 when `--min-accuracy` is not met. |
| Gold sets | `tests/fixtures/jev/<use>/gold.jsonl` + `answers.json` | One labelled row per line, with a canned `answers.json` keyed by row id so the eval runs offline and the tests pin its arithmetic. J1's rows are the unambiguous prompts of the 2026-10-23 hand-labelled window (audit §2) and the 2026-10-09 eval's shapes; J2's rows are the audit §3 cases the proxy got wrong; J9's rows are synthetic spans of the kinds `ow-protocol.md` §3d names. |

**Done when:** `npm test` passes with the new suites; `gen-route-spec --check` covers both outputs; `route-eval jev J1|J2|J9 --fixture` reports on the shipped gold sets; `docs/runbooks/skill-router-eval.md` §7 documents the command; the hook's behaviour is byte-for-byte what #654 shipped.

Two rules fall out of the investigation and hold for every row:

1. Jev adds information only where the decision is uncertain **and** the deciding party would read the answer. Between skills the row already names the next skill (J4) and the ow- family's bus is the user (J3), so neither gets a classifier.
2. A use goes to **shadow** only after its gold set passes at the threshold the caller will use, and to **live** only through a go/no-go like the router's (runbook §6).
