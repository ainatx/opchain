# The ow- site section, parked for the 2.2 cut (2026-11-05)

Owner decision 2026-11-05: 2.1.0 is the Jev and enforcement release (oc- only); the
ow- planning family, ow-tools and the `/work` site section ship with 2.2. PR #671 had
them; the strip is commit `2bdc7200` on `claude/release-2-1-0-1cd617`.

## Where the parked state lives

**Commit `b1559d18`, tagged `parked-ow-site-2-2`**, is the release branch tip before the
strip: the full ow- site state as it was reviewed (12 `/work` pages, `WorkPage`, the work
architecture diagrams, the `work` content collection, the `/work` release-surface
probes, the Worker 307 handling, `catalogs.json` `outputs.site`, the ow- mentions on
`/changelog`, `/install`, `/privacy`, `/security`, `/glossary`, `/for-agencies`,
`/architecture`, the footer, header and search palette). The tag keeps it reachable
after the release branch is squash-merged and deleted.

It is not a branch, on purpose. With `OPCHAIN_SHIP_WORK` unset (the 2.1 default),
`build-site.sh` runs `check-work-install.mjs --expect-withheld`, which refuses a
`public/work/` directory, and the `/work` pages build into exactly that. So a branch
holding the live pages cannot pass the commit gate until 2.2 turns the switch on. That
is the guard working, not a defect.
