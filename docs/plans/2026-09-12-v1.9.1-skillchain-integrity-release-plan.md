**Why a release, not a stream of fixes.** The audit's CRITICAL tier sits in shipped
product: the plugin commit gate, the checkpoint CLI, and the skill contracts that every
zip, plugin and MCP install carries. Those reach users only through a versioned catalog.
A behaviour change of this size, especially one that makes the commit gate stricter,
should carry a version number and a Compatibility note rather than drift into the public
mirror under `1.9.0`.

## 1. The patch-scope rule

`RELEASING.md` §2 defines a patch as "fixes, doc corrections, no new capability", and
`semver-decisions.md` makes a new verb, new section, new scenario or new flag a minor.
Every change in this release must therefore pass one test:

> **Does it make an existing documented behaviour true, or correct a document to match
> real behaviour?** If yes, it is in. If it adds something a consumer could not do on
> 1.9.0, it moves to v2.0.

Applied to the audit's fix plan:

| Change | Verdict | Why |
|---|---|---|
| Gate reads the documented verdict shape; tree hash excludes its own checkpoint; bypass forms closed | **In** | Makes the documented gate behave as documented. Stricter, so it gets a Compatibility callout |
| `checkpoint.mjs status <skill>` honours its argument; update operators accept either suffix order | **In** | Bug fixes to documented commands |
| Validator warns on contradictory lifecycle states | **In** | Warning-only; no checkpoint that validates today stops validating |
| Declare the sixteen documented subcommands in frontmatter `commands:` | **In** | Each already exists in its skill body. Subcommands inherit the parent verb's flag (`scripts/check-skill-flags.mjs:56-57`), so no new flag name is added |
| Repoint `/oc-rollback` and `/oc-git-commit` call sites to declared verbs | **In** | Adding either as a new root verb would be a minor; repointing is a correction |
| Orchestrator map rows, §3 handoff rows, §7 reconciled to frontmatter | **In** | Documentation catching up to the catalog |
| MCP intent routing covers all 33 skills; `/pipeline-builder` reads the live catalog | **In** | Implementation catching up to documented routing and catalog |
| New CI checks (verb-declared, §7 exact match, doctor on warnings) | **In** | Repo tooling, not a catalog surface |
| Promote cross-skill `skill_state` payloads to public checkpoint fields | **Out → v2.0 Sprint 1** | A protocol change; wire 1.2 is its vehicle |
| Register additional plugin slash commands | **Out → v2.0** | New commands for plugin users. This release only documents which twelve ship and why |
| Serve bundled `references/` over `/docs`, `/llms.txt` and MCP | **Out → v2.0** | New transport content. This release documents the limitation |
| Any `skills/` text naming `oc-hindsight`, `oc-evolve` or wire 1.2 | **Out** | The v2.0 freeze rule; `skills/` is mirrored |

## 2. `/oc-release plan` output — decision points

### D1. Version: **v1.9.1** (proposed)

Decision tree, first match wins: no checkpoint field renamed or removed (rule 1), no verb
removed (2), no skill dropped from the map (3), no skill added (4). Rule 5 is the close

`semver-decisions.md` says to err toward minor when in doubt. If you read rule 5 strictly,
the alternative is **v1.10.0** with identical scope; the only differences are the L1–L3/L6
surfaces moving and the changelog hero aging pass (`RELEASING.md` §4).

### D2. Theme name

Proposed: **"The chain holds"**. Alternative: "Handoffs that land".

### D3. Headline items, ranked by surface impact

1. **The commit gate reads the checkpoint its own skill writes.** It stops denying
   doc-conformant passes, stops deadlocking repos that track their checkpoints, and closes
   six bypass forms.
2. **Deploy and pre-PR gates stop trusting stale or missing state.** `status <skill>` fails
   on a missing checkpoint, a pre-PR pass must match the branch head, and an audit records
   what it covered.
3. **Every handoff names a command its receiver declares.** Sixteen subcommands indexed, two
   undeclared verbs repointed, and a CI check so it cannot drift back.
4. **The orchestrator map covers the whole catalog.** Eight missing map rows, handoff rows for
   seven skills, and §7 held to exact match by CI.
5. **Checkpoint tooling you can trust.** Update operators, lifecycle warnings, session-start
   rendering, and seven live checkpoints reconciled.
6. **Reach.** MCP intent routing for all 33 skills; `/pipeline-builder` on the live catalog.
7. **Corrections.** Corrupted alert hostnames, sandbox-only tool references, stale release
   references, the circular release verify, the modularize → migration handoff.

### D4. Merge strategy: continuous to `main` (proposed)

Each sprint PR merges to `main` when green; the version bump and changelog heading happen
once, in the product-half PR. This is the v1.8.3 precedent. The trade-off is that fixed
hooks reach the public mirror under `1.9.0` before the tag. The alternative, a
`release/v1.9.1` integration branch merged once, keeps the public plugin changing in a
single step at the cost of a long-lived branch.

**Safety valve:** if Sprint 5 is still open two weeks after Sprint 1 merges, cut v1.9.1 at
the end of Sprint 3 and roll Sprints 4–6 into v1.9.2.

### D5. Staging returns to `main` now (proposed, owner action)

contrary to #490's own deploy rule, and keeps the scheduled Canary's staging half red.
