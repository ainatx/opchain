ENFORCEMENT MAP · orchestrator.md §3
Where each edge that must hold is held, and by what

Ordered along the lifecycle. Each card is one chokepoint, and the numbered ◆ in the dimmed bands shows where it sits. If a row's mechanism is not installed in the repository you are working in, that edge is prose there: install it with /oc-enroll, install-git-drivers --ci or the deploy wrapper before relying on it.

1spec → build
The spec phase produces its artifacts
scaffold-spec writes spec/01…10 stubs whose first line names the producing skill.
Once oc-app-architect's checkpoint is in a build phase, the enrolled gate refuses a commit while a stub still carries its producer line.
2git commit
Every commit passes bug-check
Enrolled pre-commit verifier (/oc-enroll) writes tree-bound receipts: PASS, FAIL, UNSUPPORTED or INCONCLUSIVE.
A timeout, exit 127 or environment failure gives INCONCLUSIVE (exit 2): retry it, there is nothing to fix. Only PASS authorizes.
3post-commit
A bypass is a recorded event
Git runs post-commit even under --no-verify. It writes .git/opchain/bypasses/v1/<sha>.json for any commit with no PASS receipt.
This hook cannot block a commit that already exists. It records the bypass so the push step can see it.
4git push
Bypassed commits do not leave the machine silently
pre-push refuses a recorded bypass until the commit carries a bugcheck: bypassed (<reason>) trailer.
Audit I-04 counted ≥18 unrecorded bypasses before this guard existed.
5PR open
Every PR carries docs + readiness evidence
CI evidence:pr (release-evidence.mjs --stage pr) requires pr-docs-v1 (oc-docs-forge) and pr-readiness-v1 (oc-repo-ops) handoffs bound to the HEAD tree.
A consumer repo gets the workflow from install-git-drivers --ci.
6release
Releases are tagged before they ship
check-release-tag refuses a production deploy of an untagged catalog version (signed tag).
The SessionStart release-resume line names /oc-git-release <semver> while oc-release-ops is phase=ship and the tag or live SHA is missing.
7deploy
Deploys ship reviewed main
The deploy wrapper checks the exact origin/main for staging, the live-SHA ancestor, and an explicit production token.
It writes .checkpoints/oc-deploy-ops.checkpoint.json on every run.
8artifact-keyed rows
Security, integration and eval reviews happen
.opchain/hardening.yaml + security_review_ref (deploy replays /oc-harden verify). A new *_API_TOKEN needs integrations/<service>.md. A prompt-file commit needs a current eval score.
These rows apply at commit or deploy, and only when their artifact exists.
Held: the native pre-commit gate was the only enforcement that held (FAIL 41% deftwright / 22% opchain). Not a gate: the Jev router only suggests and never blocks. It runs in shadow mode by default.

Every prompt · routed, never blocking
Session hooks and the Jev skill router
The UserPromptSubmit hook redacts the prompt and sends it to TypeSafe Jev with the conversation tail and repo state. Request 1 is a Choice over every routable skill plus none, with three gate Nouls. Request 2 reranks the top 3, with a fits Noul and a verb Choice per candidate. A suggestion needs gate ≥ 0.5, top probability ≥ 0.35, fits ≥ 0.4 for the 7 core skills (0.9 for the rest), and membership in the 12-skill evidence allowlist. The output is the one line the audit measured at 72/72: invoke the Skill tool with skill X and args /verb.
An explicit /oc-* mention routes deterministically with no Jev call. Shadow mode is the default: it logs and injects nothing. Each prompt also appends an outcome record for the previous one (skill calls, commit, push, PR, deploy), which route-eval outcomes uses for the go/no-go decision. SessionStart and Stop only inform; neither is a gate.

What held (audit 2026-10-08)

  • · The native git pre-commit verifier was the only enforcement that held. Its FAIL rate was 41% in deftwright and 22% in opchain.
  • · docs-forge → repo-ops was the one chain edge that held, because CI checks it (evidence:pr).
  • · Tool-named spawn prompts got 72/72 invocations; the /oc-code-auditor shorthand got 80/143 (one lane 0/33).

What did not

  • · Prose skill-to-skill handoffs produced zero autonomous invocations across 87 sessions.
  • · 0/229 deftwright PRs entered oc-git-ops. Claude Code's built-in gh pr create recipe won every time.
  • · Stop next-suggestion was followed 0/62 times. SessionStart state fired 53/55 and 27/41 sessions and was acted on in the first turn ≤1 and ≤4 times.

Jev router status (uncommitted)

  • · Shadow mode is the default. Injection requires OPCHAIN_ROUTE_MODE=live.
  • · The 2026-10-09 blind-labelled eval used 574 prompts with 41 positives. It set the tiered fits bar and the 12-skill allowlist.
  • · Go/no-go comes from route-eval outcomes over shadow-run outcome records (the day-8 check).
